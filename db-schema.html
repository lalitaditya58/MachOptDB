Database Schema

MachOptDB relational database structure

MachOptDB — Relational Database Design

Eight connected tables store workpiece, tool, machine, operator, experiment, result, energy and cost information for CNC machining analysis.

Workpiece

Stores machining material properties.

ColumnKey / Type
Workpiece_IDPK VARCHAR
Material_NameVARCHAR
Hardness_HBDECIMAL
Density_g_cm3DECIMAL

Cutting_Tool

Stores cutting-tool specifications and cost.

ColumnKey / Type
Tool_IDPK VARCHAR
Tool_MaterialVARCHAR
Tool_Diameter_mmDECIMAL
Tool_CostDECIMAL

Machine

Stores CNC machine capability information.

ColumnKey / Type
Machine_IDPK VARCHAR
Machine_NameVARCHAR
Maximum_RPMINT
Power_kWDECIMAL

Operator

Stores operator information used in experiments.

ColumnKey / Type
Operator_IDPK VARCHAR
Operator_NameVARCHAR
Experience_YearsDECIMAL

Machining_Experiment

Central table containing machining parameters and references.

ColumnKey / Type
Experiment_IDPK VARCHAR
Workpiece_IDFK VARCHAR
Tool_IDFK VARCHAR
Machine_IDFK VARCHAR
Operator_IDFK VARCHAR
Cutting_Speed_m_minDECIMAL
Feed_Rate_mm_minDECIMAL
Depth_of_Cut_mmDECIMAL
Machining_Time_minDECIMAL

Machining_Result

Stores measured machining-performance results.

ColumnKey / Type
Result_IDPK VARCHAR
Experiment_IDFK VARCHAR
Tool_Wear_mmDECIMAL
Surface_Roughness_umDECIMAL
Material_Removal_Rate_cm3_minDECIMAL

Energy_Consumption

Stores energy used by each experiment.

ColumnKey / Type
Energy_IDPK VARCHAR
Experiment_IDFK VARCHAR
Energy_kWh / Energy_Consumed_kWhDECIMAL

Machining_Cost

Stores labor, energy and total machining cost.

ColumnKey / Type
Cost_IDPK VARCHAR

Labor_CostDECIMAL
Energy_CostDECIMAL
Total_CostDECIMAL

Table Relationships

Primary and foreign-key relationships used by MachOptDB.

  • Workpiece 1 → many Machining_Experiment
  • Cutting_Tool 1 → many Machining_Experiment
  • Machine 1 → many Machining_Experiment
  • Operator 1 → many Machining_Experiment
  • Machining_Experiment 1 → 1 Machining_Result
  • Machining_Experiment 1 → 1 Energy_Consumption
  • Machining_Experiment 1 → 1 Machining_Cost
DBMS design: MachOptDB uses a centralized relational structure so machining experiments can be joined with material, tool, machine, operator, result, energy and cost information for SQL-based analysis.
